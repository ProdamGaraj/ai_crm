## Сценарии тестирования

### 1. Тест разрешений по ресурсам

**Войдите как manager1:**
- ✅ Должен видеть клиентов и сделки
- ✅ Должен иметь возможность создавать клиентов
- ✅ Должен иметь возможность создавать сделки
- ❌ НЕ должен видеть кнопку "Создать проект"

**Войдите как director1:**
- ✅ Должен видеть клиентов, сделки и проекты
- ✅ Должен иметь возможность создавать всё

**Войдите как viewer1:**
- ✅ Должен видеть все данные
- ❌ НЕ должен видеть кнопки создания/редактирования/удаления

### 2. Тест изоляции компаний

**Создайте клиента от manager1 (Компания 1):**
- manager1 должен видеть этого клиента
- manager2 должен видеть этого клиента (та же компания)
- director1 должен видеть этого клиента (та же компания)
- manager_company2 НЕ должен видеть этого клиента (другая компания)
- viewer1 НЕ должен видеть этого клиента (другая компания)

### 3. Тест изоляции отделов

**Создайте сделку от manager1 (Отдел продаж):**
- manager1 должен видеть эту сделку
- manager2 может или не может видеть (зависит от scope разрешения)
- director1 должен видеть эту сделку

### 4. Тест системы входа

1. Откройте http://localhost:5173
2. Вы должны увидеть страницу входа
3. Войдите как **manager1** / **test123456**
4. Вы должны быть перенаправлены на дашборд
5. В правом верхнем углу должно быть имя "Иван Менеджеров"

## Исправленные проблемы

### Проблема с созданием ролей через UI
**Симптом**: Роли не создавались через форму в UI  
**Причина**: Форма отправляла `permissions` как массив ID, но backend ожидал `permission_ids`  
**Решение**: Исправлена RoleForm.tsx - теперь преобразует `permissions` → `permission_ids` перед отправкой

### Файл: `frontend-new/src/components/permissions/RoleForm.tsx`
```typescript
const payload = {
  ...data,
  permission_ids: data.permissions,
};
delete payload.permissions;
```

## Дополнительная информация

### Проверка текущих пользователей
```bash
cd backend
py.exe manage.py shell

from django.contrib.auth.models import User
from permissions.models import UserProfile

# Список всех пользователей
for profile in UserProfile.objects.select_related('user', 'company', 'department').all():
    print(f"{profile.user.username} - {profile.user.get_full_name()} - {profile.company.name}")
```

### Удаление тестовых данных
Если нужно удалить все тестовые данные и создать заново:

```python
# В Django shell
from django.contrib.auth.models import User
from permissions.models import Company, Department, Role, UserProfile

# Удалить тестовых пользователей
User.objects.filter(username__in=['manager1', 'manager2', 'director1', 'viewer1', 'manager_company2']).delete()

# Удалить тестовые роли
Role.objects.filter(code__in=['MANAGER', 'DIRECTOR', 'VIEWER']).delete()

# Удалить тестовые компании (cascade удалит отделы и профили)
Company.objects.filter(code__in=['COMPANY1', 'COMPANY2']).delete()
```

Затем снова запустите:
```bash
py.exe manage.py create_test_users
```

## Рекомендации по тестированию

1. **Тестируйте в разных браузерах**: Откройте несколько окон браузера (или используйте режим инкогнито) для одновременного входа разными пользователями

2. **Проверяйте логи**: Backend выводит в консоль информацию о проверке разрешений

3. **Тестируйте API напрямую**: Используйте Postman или curl для тестирования API endpoints с разными токенами

4. **Проверяйте изоляцию данных**: Убедитесь, что пользователи из разных компаний не видят данные друг друга

5. **Тестируйте восстановление пароля**: Для каждого пользователя можно протестировать функцию "Забыли пароль?"
